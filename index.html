01
Why this exists

The original showed me how it works. My own testing showed me what I wanted different.

I used WinMemoryCleaner because it exposed operations Windows normally hides. While using it I hit three things I wanted to change — and none of them is a defect in the original. They are the things a second implementation can do differently.

Responsiveness

A cleanup issues system calls that can take a moment. When that work shares a thread with the interface, the window stops answering while it runs. The next generation puts every operation on its own thread and keeps the UI free to redraw.

Control

Background behaviour should be something you set, not something you notice. Automation here is off until you enable it, with an explicit trigger, a cooldown and a latch so a machine resting at its threshold cannot be cleaned in a loop.

Visibility

Freed 1.2 GB is not an answer if you cannot see which operation released what. Every run here records a per-operation result, the trigger, the duration and the errors — and reports a failure as a failure.

03
Evolution

Built on inspiration. Re-engineered for what comes next.

Two generations, two codebases, one idea: let a user see and control the memory operations Windows performs on their behalf. The second was written after studying the first.

Generation 1

WinMemoryCleaner

by Igor Mundstein · GPL-3.0-or-later

A focused Windows utility that put memory-management operations in front of the user: working sets, the standby list, system file cache and the combined page list. It showed that these mechanisms are reachable from a normal desktop application, and its documentation and behaviour became the starting point for my own investigation.

What I ran into while using and testing it

  • The window could feel unresponsive while an operation was running.
  • Some operations produced noticeable pauses elsewhere in the system.
  • Control over background behaviour and scheduling was limited.
  • Per-operation results were harder to read than I wanted.
github.com/IgorMundstein/WinMemoryCleaner
Generation 2

Windows Memory Cleaner NG

by Kabbali Gamer · proprietary, free to use · v2.0.1

An independent implementation written from scratch. The Windows calls, measurement model, interface, automation engine, storage format and packaging were all designed for this project — nothing was copied, and no source from the original is included or adapted.

What is different by construction

  • One Rust backend owns every Win32 call; the UI never blocks on one.
  • Cleanups run on their own thread and report per-operation outcomes.
  • Automation is opt-in, with cooldown, hysteresis and a pause switch.
  • Startup apps are manageable — the change that survives a reboot.
  • Logs and diagnostic exports are redacted before they reach disk.
  • No network client, no telemetry, no update check.
github.com/kabaliGamer-Dev2/windows-memory-cleaner-ng

Independently developed. This is a next-generation implementation inspired by the original WinMemoryCleaner project. It is not affiliated with, endorsed by, sponsored by or a collaboration with Igor Mundstein, and the two projects share no ownership.

04
Features

Eight pages. No filler on any of them.

Each screen exists because a specific question had no honest answer elsewhere: what is cached, what is each process holding, what ran last night, and what starts without asking.

Memory Cleaner
01 — Memory Cleaner

Pick the operation, not the magic button

Eight Windows memory operations, each one a documented API call with its own cost. You choose which to run; the page shows which of them your current permission level allows before you click anything.

  • Working sets · standby list · modified page list · file cache
  • Combined page list · registry cache · volume cache
  • A per-operation result, not one combined number

Some operations are marked disruptive. Flushing the file cache costs disk activity, and the application says so rather than hiding it behind a single button.

Memory Monitor
02 — Memory Monitor

Watch the trend, not a frozen percentage

A single number tells you nothing about direction. The monitor keeps a rolling window of load, available, cached and committed memory so you can see whether the machine is settling or climbing.

  • Four series, one time axis
  • Sampling interval you control
  • Charts drawn as plain SVG — no chart library loaded
Processes
03 — Processes

Trim a working set. Never end a process.

Every row shows what a program is holding. Trimming asks that program to release the memory it loaded but is not currently using — the pages come back the moment it needs them, and the program keeps running.

  • Working set and private bytes per process
  • An exclusion list for anything you never want touched
  • No terminate action exists anywhere in the application
Automation
04 — Automation

Off until you turn it on, and never a surprise

Automation runs the operations you selected when a threshold is crossed, on a fixed interval, or on either — whichever comes first. A cooldown always applies, and a run is skipped when your selected operations have almost nothing to release.

  • Threshold presets from 50 % to 90 %, or any value
  • Intervals from 15 minutes to 24 hours, or custom
  • Next run, last run, and the reason it last did nothing

Automatic cleaning needs Administrator rights. If the window is not elevated, the application says so and offers the elevation instead of quietly recording failures.

Activity
05 — Activity

A receipt for every run

Each entry records what triggered the run, how long it took and what each operation returned. A failed run is stored as a failure — it does not inherit a number from something the system happened to do at the same moment.

  • Trigger, duration and per-operation outcome
  • History depth you configure
  • Zero bytes means zero bytes
Startup Apps
06 — Startup Apps

The only change here that lasts

Clearing memory is temporary by design — Windows refills the cache. A program that starts with your session keeps running for as long as it runs. Turning it off is what durably reduces what your machine loads at sign-in.

  • Reads both registry Run keys and both Startup folders
  • Per-user entries switch off reversibly — nothing is deleted
  • Machine-wide entries are listed but marked read-only
Settings
07 — Settings

Everything written down, nothing guessed

Appearance, sampling interval, history depth, launch behaviour, process exclusions and log level live here. Every setting persists to a readable JSON file you can inspect.

  • Start with Windows, or ask for Administrator rights at launch
  • Process exclusions matched case-insensitively
  • Diagnostics export for a bug report
Keyboard shortcuts
08 — Shortcuts

Three keys, while the window is in the tray

Global shortcuts work when the application is minimised. They are configurable and can be disabled, and a combination already owned by another program is reported rather than silently ignored.

  • Ctrl + Alt + M — run the configured operations now
  • Ctrl + Alt + P — pause or resume automation
  • Ctrl + Alt + S — bring the window to the front
05
Engineering

Engineered around performance

Performance here means three specific things, and it is worth being precise about which: the window keeps answering, background work is bounded, and every result can be traced to a call that produced it.

Engineering decisions and their effect
DecisionWhy it matters
All system calls live in one Rust backend The UI cannot issue an unbounded number of system calls, and a slow call cannot freeze a render.
Cleanups execute on a dedicated thread The interface keeps repainting while an operation runs, so progress is visible instead of a frozen window.
Sampling is a fixed cadence, not a loop One reading per interval (250 ms to 10 s, your choice) instead of continuous polling — the cost is predictable and configurable.
History is capped in memory 30 to 600 samples and a bounded run list, so a long session cannot grow without limit.
The log rotates at 2 MB Diagnostics stay useful without filling the disk over months of use.
Disruptive operations are labelled Flushing the file cache costs disk activity; the interface says so before you select it rather than after.
Per-operation error capture A refused call is recorded with the privilege it needed, which turns "it did nothing" into a specific, fixable message.

What was measured, and what was not

These figures come from one machine running the released build. They are measurements, not a benchmark suite, and they are reported with their environment so you can judge how much they apply to you.

Memory cleaning is not a speed-up. Windows keeps free RAM as cache on purpose and refills it after a purge. What this application changes is which pages are held and how visible that is — not how fast your processor runs. The durable change you can make is on the Startup Apps page: fewer programs loading at sign-in.

Backend and Windows integration

  • Rust 2021 editionEvery system call. No garbage collector between you and a memory measurement.
  • windows-sys 0.61Fifteen Win32 feature gates, used directly — there is no third-party memory-cleaning library underneath.

How it works

From download to a number you trust, in seven steps

No account, no wizard, no onboarding sequence. Install it, look at the dashboard, choose what to run.

  1. 01

    Download the application

    Take the installer if you want a Start Menu entry, or the portable file if you just want to run it.

  2. 02

    Install, or do not

    The installer works per-user and needs no administrator rights to install. The portable executable needs nothing at all.

  3. 03

    Open the dashboard

    Memory in use, available, cached and committed, live, with the pressure level Windows reports.

  4. 04

    Look before you act

    Check the monitor for a trend and the processes page to see who is actually holding memory.

  5. 05

    Select operations

    On the Memory Cleaner page, tick the operations you want. Anything that needs elevation is marked before you run it.

  6. 06

    Run them

    Press Run selected. If the selection needs Administrator rights, the button becomes Clean as Administrator and asks Windows for them.

  7. 07

    Read the result

    Each operation reports what it did. The run appears in Activity. If nothing was released, it says nothing was released.

Automation

Set a rule once, then forget it

Automation is off by default. When you turn it on you choose what makes a run due, what it is allowed to do, and how often at most.

Triggers
Memory threshold, fixed interval, or either
Threshold
Presets at 50, 60, 70, 75, 80, 85, 90 percent, or any value
Interval
15 m to 24 h in presets, or a custom period
Cooldown
A minimum gap is always enforced between runs
Hysteresis
After a run the trigger stays latched until load falls below the threshold again, so memory hovering at the limit cannot fire repeatedly
Pause
Stop automatic runs without losing your configuration
Permissions
Needs Administrator. The page offers the elevation rather than failing quietly

Safety & transparency

The list of things it will not do is longer than the list of things it will

A memory utility earns trust by its limits. These are the limits, and they are enforced in the code rather than stated in a policy.

What it does

  • Measures memory before and after every run, and reports both
  • Asks Windows to release standby, cached and working-set memory
  • Lists startup programs and switches per-user ones off reversibly
  • Keeps a local history, a local log and a readable settings file
  • Writes one registry value, only if you enable start-with-Windows

What it does not do

  • Terminate processes, or close the programs you are running
  • Touch the pagefile, SSD or TRIM settings, or firmware
  • Disable Windows services, scheduled tasks, Defender, the firewall or Windows Update
  • Connect to the network at runtime, or collect telemetry
  • Promise a permanent speed-up. Windows refills the cache by design

Privacy

What leaves this computer: nothing

This is a statement about the desktop application, and it is verifiable rather than aspirational: the published executable imports no network library at all — no WinHTTP, no WinINet, no DNS client, no socket API. Everything it writes stays in one folder you can read.

Stored locally, nothing else

  • settings.json — preferences and exclusions
  • history.json — past runs and their results
  • logs\application.log — diagnostics, 2 MB cap
  • No network library is linked into the executable: no WinHTTP, WinINet, DNS or socket import
  • Logs and exports are redacted before writing: profile paths become %USERPROFILE%, the machine and account names become placeholders
  • The window shows “This device” and “Current user” until you opt in

Never sent anywhere

  • No telemetry and no analytics
  • No crash reporting and no update check
  • No account, no licence server, no cloud sync
  • No API keys, tokens or credentials — the binary contains none
  • No MAC address, serial number, product key or recovery key is read, stored or displayed

To remove everything the application has stored, close it and delete %APPDATA%\WindowsMemoryCleanerNG. The website has its own policy — it is hosted by GitHub Pages and sets no cookies, runs no analytics and loads no third-party scripts. The full detail is in the privacy policy.
