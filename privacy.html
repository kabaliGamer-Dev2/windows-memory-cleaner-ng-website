Privacy Policy

Last updated 19 November 2026

These are two different things. This policy covers the website you are reading and the desktop application separately. The application makes no network connections at runtime and collects no telemetry. That statement applies to the application. The website is hosted on GitHub Pages, which is a third-party service and does log requests — that is described below, because it would be dishonest to leave it implied.

Part 1 — This website

Hosting logs

This site is served by GitHub Pages. When you load a page, GitHub's servers receive your IP address, the page you requested, your browser's user agent and the time of the request, in the same way any web server does. That is processed by GitHub under the GitHub Privacy Statement, not by me. I do not receive those logs and cannot identify individual visitors from them.

Cookies

This site sets no cookies.

Analytics

There is no analytics of any kind: no Google Analytics, no self-hosted analytics, no counting pixels, no session recording. I do not know how many people visit or which pages they read.

Third-party requests

The site loads no third-party scripts, stylesheets or fonts. The typeface is served from this domain as a .woff2 file, so no request goes to a font CDN and your IP address is not shared with one. The only external destinations are links you choose to follow — to GitHub, for example — and those are governed by their own policies.

Local storage

This site uses no cookies, no localStorage and no sessionStorage.

Downloads

If a release is published, download links point at GitHub release assets. Your download is served by GitHub and is subject to their logging, not mine. The checksums published next to a download let you verify the file yourself without trusting the transfer.

Part 2 — The desktop application

What it stores

Everything the application writes stays on your machine, in one folder:

  • settings.json — your preferences, including any process exclusions you add;
  • history.json — the record of past cleanup runs;
  • logs\application.log — a diagnostic log, rotated at 2 MB.

These are plain files. You can read them, back them up or delete them. Deleting the folder resets the application to defaults.

What it sends

Nothing. The application makes no network connections at runtime. It has no update check, no crash reporting, no usage statistics and no licence server. You can confirm this with any network monitor, or by reading the network section of the repository's security policy.

What it reads

It reads Windows memory counters and the list of running processes — that is what a memory utility does. It also reads startup entries from the registry and the Startup folders when you open the Startup Apps page. It does not read the contents of your documents, browser history, clipboard or keystrokes.

Redaction

The log and the diagnostics export are redacted before they are written: a path such as C:\Users\<name>\AppData\... becomes %USERPROFILE%\AppData\..., and the machine and account names are replaced with placeholders. That means a log you attach to a bug report does not identify you. The window shows “This device” and “Current user” instead of the real names until you turn that off in Settings, so a screenshot or a screen share does not carry them either.

The one registry write

If you enable Start with Windows, it writes a single value under HKCU\...\CurrentVersion\Run. Turning the setting off removes it. Switching a startup program off writes the same StartupApproved flag Windows itself uses; it never deletes a startup command.

Part 3 — Your choices

  • Do not want the site to see your request? Use a proxy or a VPN — but GitHub still sees whatever reaches it.
  • Do not want the application to keep history? Lower the history depth in Settings, or delete the folder.
  • Do not want it starting with Windows? Leave that setting off; it is off by default.

Part 4 — Changes

If this policy changes, the date at the top changes with it. Material changes will be noted in the project's changelog.

Part 5 — Contact

Privacy questions can be raised through the project's issue tracker. Security reports should follow the security policy instead of a public issue.
